# E2 - Temporal information

**Question:** Does temporal ordering improve matching and prediction, compared with a static (order-free) graph?

Sample: 24 synthetic incidents from 4 attack templates (6 each), one dataset, one seed. No confidence intervals are given because the incidents are not independent draws; treat differences of a few points as noise.

**Metrics:** top1: the true next technique is the first prediction (ties broken by technique id). top1_tie: the same, but a target tied for first with m - 1 others counts 1/m, which removes alphabetical luck. top3: the target is among the first three. mrr: mean of 1/rank over the model's full ranking, 0 if the target is not ranked (the API exposes only the top 5). precision / recall / f1: macro-averaged over the techniques that occur as targets, using the top prediction only. An instance is one prefix of one incident's trajectory; an incident with L steps gives L - 1 instances.

## What the numbers show

- Matching, ground-truth trajectories: the incident's own reference is the unique top match for 17 of 18 incidents with the static graph and 17 of 18 with the temporal graph. Order does not improve matching on this dataset.
- Prediction, ground-truth trajectories, hand-written sequences: temporal Top-1 is higher (65 vs 30 of 90), Top-3 is lower (0.789 vs 0.800), MRR is higher (0.752 vs 0.562).
- Prediction, ground-truth trajectories, groups + hand-written, pooled: temporal Top-1 is higher (28 vs 22 of 90), Top-3 is higher (0.411 vs 0.311), MRR is higher (0.423 vs 0.327).
- Prediction, ground-truth trajectories, hand-written minus own family's reference: temporal Top-1 is no different (25 vs 24 of 90), Top-3 is lower (0.444 vs 0.456), MRR is lower (0.357 vs 0.378).
- Prediction, ground-truth trajectories, hand-written + all other incidents: temporal Top-1 is higher (73 vs 36 of 90), Top-3 is higher (0.833 vs 0.789), MRR is higher (0.822 vs 0.607).
- Summary, ground-truth trajectories: temporal has the higher Top-1 in 3 of 4 training conditions and the higher Top-3 in 2 of 4. Temporal wins Top-1 where the training data contains the attack's own reference or sibling incidents, which the Markov model can replay; with the reference removed there is no Top-1 difference.
- Matching, pipeline trajectories: the incident's own reference is the unique top match for 9 of 18 incidents with the static graph and 9 of 18 with the temporal graph. Order does not improve matching on this dataset.
- Prediction, pipeline trajectories, hand-written sequences: temporal Top-1 is higher (33 vs 17 of 69), Top-3 is lower (0.565 vs 0.652), MRR is higher (0.524 vs 0.455).
- Prediction, pipeline trajectories, groups + hand-written, pooled: temporal Top-1 is lower (12 vs 17 of 69), Top-3 is lower (0.203 vs 0.333), MRR is lower (0.255 vs 0.335).
- Prediction, pipeline trajectories, hand-written minus own family's reference: temporal Top-1 is no different (13 vs 14 of 69), Top-3 is higher (0.377 vs 0.362), MRR is lower (0.276 vs 0.312).
- Prediction, pipeline trajectories, hand-written + all other incidents: temporal Top-1 is higher (39 vs 30 of 69), Top-3 is lower (0.609 vs 0.638), MRR is higher (0.594 vs 0.552).
- Summary, pipeline trajectories: temporal has the higher Top-1 in 2 of 4 training conditions and the higher Top-3 in 1 of 4. Temporal wins Top-1 where the training data contains the attack's own reference or sibling incidents, which the Markov model can replay; with the reference removed there is no Top-1 difference.

## Caveats

- What E2 supports: order does not improve historical matching on this dataset, and order raises Top-1 prediction only when the model can replay a memorised sequence. What it does not support: a general advantage of the temporal graph.
- Patterns A, B and C already differ in WHICH techniques they contain, so set overlap alone tells them apart. A dataset with patterns that use the same techniques in different orders would test matching properly; this one contains none.
- The reversed-order table is a control that holds by construction (set overlap cannot see order); it shows the mechanism works, not that order matters in practice.
- With the reference in the history, part of the Top-1 gap is by construction: a set-based model cannot rank the remaining members of a matching set, while the Markov model replays the sequence. Top-3 is the fairer comparison.
- The static predictor never proposes a technique already in the path. The target is already in the path for 0 of 90 ground-truth instances and 5 of 69 pipeline instances, so this caps static only on pipeline trajectories.
- Pipeline trajectories: 1 of 24 true incidents have no inferred trajectory and 3 have a single step, so the prediction rows cover the remaining incidents only (survivors). The matching table counts a missing trajectory as a miss; the control table leaves it out.
- On pipeline trajectories the prediction target is the pipeline's own next step, mapping errors included; those rows compare the two methods on the same noisy input and are not end-to-end accuracy.
- 'Static' and 'temporal' are two scoring rules over the same data. The Neo4j graph always stores NEXT edges; the static condition simply does not use the order.
